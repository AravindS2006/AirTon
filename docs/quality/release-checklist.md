# Release gates

## Research software release

- Reproducible commands and relevant checks pass; limitations match implementation.
- Claims, source register and project status updated.
- Only synthetic examples or approved shareable artifacts included.
- Dependency/runtime versions and artifact provenance recorded.
- No secrets, identifying records, restricted data or invented approvals.
- Licensing/IP/publication status reviewed before making the repository public.

## Device or clinical release - all still open

- Approved intended use, regulatory classification/path and quality responsibilities.
- Reviewed design inputs, full applicable standards crosswalk and traceability.
- Physical pneumatic/optical/electrical safety evidence and independent controls.
- Calibrated measurement system with approved agreement/repeatability evidence.
- Required ethics/regulatory permissions and reviewed clinical study results.
- Approved model/data lineage, independent evaluation and domain limitations.
- Representative operator usability and clear instructions/labeling.
- Production identity, authorization, privacy, audit, backup and incident evidence.
- Training, calibration/service, post-release surveillance and change control.

The second list is not completed by the first. Release authority and reviewer
identities must be assigned by the team, not generated by a template.
